# نظام التوصيات الإسلامي ومساعد بينانس اليدوي

يقرأ النظام توصيات العملات الرقمية من قنوات تيليجرام، ويستخرج بيانات الصفقة، ويتحقق من حكم العملة عبر بوت فحص خارجي، ثم يجلب سعر بينانس ويرسل تفاصيل التنفيذ اليدوي إلى بوت تيليجرام الخاص بك. **لا ينفّذ النظام أي تداول آلي.**

الوضع الموصى به لهذا المشروع هو **المسح المجدول**: يشغّل Cron عملية قصيرة ثلاث مرات يوميًا، تقرأ صفقات اليوم ثم تنتهي. لذلك لا تحتاج إلى إبقاء مستمع Telethon يعمل طوال اليوم.

## نمطا التشغيل

| النمط | الأمر | السلوك | المكان المناسب |
|---|---|---|---|
| المسح المجدول — الموصى به | `python batch_scan.py` | يفحص رسائل اليوم مرة واحدة، يرسل النتائج ثم يغلق اتصال تيليجرام ويخرج | Namecheap Shared Hosting أو أي خادم يدعم Python وCron |
| الاستماع اللحظي — اختياري | `python main.py` | يبقى متصلًا ويلتقط كل رسالة جديدة ويشغّل أوامر الإدارة ولوحة الويب | جهاز محلي أو VPS يسمح بعملية دائمة |

في النمط المجدول لا تعمل أوامر `/add` و`/channels` و`/del` و`/bot` و`/check` بين مواعيد Cron، لأن العملية تكون متوقفة. القنوات والإعدادات المحفوظة في `channels.json` و`settings.json` تبقى مستخدمة في كل مسح.

## حساب تيليجرام والبوتان المستخدمان

هناك ثلاثة أدوار مختلفة، ولا يجوز الخلط بينها:

| المكوّن | وظيفته | الإعداد |
|---|---|---|
| حسابك الشخصي عبر Telethon | قراءة القنوات وإرسال رمز العملة إلى بوت الفحص | `TG_API_ID` و`TG_API_HASH` وملف `crypto_listener_session.session` |
| بوت الفحص الشرعي الخارجي | يستقبل رمزًا مثل `BULLA` ويعيد الحكم | `HALAL_BOT_USERNAME`، ولا يحتاج المشروع إلى توكن هذا البوت |
| بوت الإشعارات الخاص بك | يرسل نتيجة الصفقة إلى هاتفك | `TG_BOT_TOKEN` و`ADMIN_CHAT_ID` |

ملف الجلسة يجب أن يكون لحساب تيليجرام **شخصي** منضم إلى قنوات التوصيات، وليس جلسة بوت. أما `TG_BOT_TOKEN` فلا يُستخدم لقراءة القنوات؛ وظيفته إرسال الإشعارات النهائية فقط.

### قراءة رد بوت الفحص

الإعداد المناسب للبوت الذي يكتفي باسم العملة هو:

```env
HALAL_BOT_USERNAME=@CryptoGulfHalal_Bot
HALAL_BOT_QUERY_TEMPLATE={coin}
```

سيرسل النظام `BULLA` مثلًا دون أمر إضافي. إذا أعاد بوت الفحص صورة ومعها وصف نصي (caption)، فإن Telethon يضع الوصف في `raw_text` ويقرأ النظام منه عبارات مثل `مباح` و`غير مباح`؛ لذلك لا يحتاج إلى OCR. إذا أعاد صورة بلا أي وصف نصي فلن يستطيع النظام استنتاج الحكم من شكل الصورة وحده.

قيم `.env` السابقة هي القيم الأولية. إذا كان `settings.json` موجودًا، فإن اسم بوت الفحص وصيغة السؤال المحفوظين فيه لهما الأولوية؛ تأكد أنه يحتوي البوت الصحيح قبل تفعيل Cron.

### تجهيز بوت الإشعارات

1. أنشئ بوتك من `@BotFather` وانسخ التوكن إلى `TG_BOT_TOKEN`.
2. افتح محادثة بوتك من الهاتف واضغط **Start** أو أرسل `/start` مرة واحدة. تيليجرام لا يسمح للبوت ببدء محادثة خاصة معك قبل ذلك.
3. ضع رقم محادثتك في `ADMIN_CHAT_ID`؛ يجب أن يكون Chat ID رقميًا، وليس اسم المستخدم.

مثال:

```env
TG_BOT_TOKEN=123456789:ضع_توكن_بوتك_هنا
ADMIN_CHAT_ID=987654321
```

بعد فحص الصفقة، يرسل هذا البوت إلى هاتفك الزوج والمصدر والحكم والسعر اللحظي والدخول والأهداف ووقف الخسارة وتحليل المخاطرة والعائد. لا يحتاج استقبال هذه الرسائل إلى تطبيق إضافي غير تيليجرام.

## آلية المسح المجدول

في كل تشغيل ينفّذ `batch_scan.py` الخطوات التالية ثم يخرج:

1. يتصل بحسابك الشخصي من خلال جلسة Telethon.
2. يقرأ رسائل **اليوم** من كل القنوات المسجلة.
3. يمنع إعادة معالجة الرسالة نفسها باستخدام معرّف القناة ورقم الرسالة.
4. يستخرج الزوج والدخول والأهداف ووقف الخسارة.
5. يسأل بوت الفحص الشرعي برمز العملة فقط ويقرأ النص أو caption من الرد.
6. يجلب السعر اللحظي من بينانس ويحسب المخاطرة والعائد.
7. يحفظ النتائج ويرسل إشعار تيليجرام للصفقات المقبولة وفق إعدادات المشروع.
8. يغلق الاتصال وينهي العملية؛ لا يبقى daemon أو مستمع في الخلفية.

تُحسب بداية ونهاية «اليوم» وفق `APP_TIMEZONE`، بينما **موعد إطلاق العملية نفسها يحدده Cron**. في وضع batch لا تطلق قيمتا `DAILY_SCAN_ENABLED` و`DAILY_SCAN_TIMES` أي عملية من تلقاء نفسيهما؛ هما خاصتان بالمجدول الداخلي عند تشغيل `main.py` باستمرار.

## التشغيل المحلي أول مرة

1. ثبّت المتطلبات:

   ```bash
   pip install -r requirements.txt
   ```

2. انسخ `.env.example` إلى `.env` وأدخل القيم الأساسية:

   ```env
   TG_API_ID=12345678
   TG_API_HASH=ضع_api_hash_هنا
   TG_BOT_TOKEN=ضع_توكن_بوت_الإشعارات_هنا
   ADMIN_CHAT_ID=987654321

   HALAL_BOT_USERNAME=@CryptoGulfHalal_Bot
   HALAL_BOT_QUERY_TEMPLATE={coin}
   HALAL_BOT_TIMEOUT=30
   HALAL_CACHE_DAYS=7

   APP_TIMEZONE=Asia/Riyadh
   ```

3. أنشئ جلسة Telethon بحسابك الشخصي مسبقًا بتشغيل `python main.py` مرة واحدة من طرفية تفاعلية، ثم أدخل رقم الهاتف ورمز التحقق. بعد إنشاء `crypto_listener_session.session` أوقف `main.py` واستخدم المسح المجدول. إذا سبق إنشاء الملف كجلسة بوت، فأوقف التشغيل وانقل الملف القديم إلى نسخة احتياطية ثم أعد تسجيل الدخول برقم حسابك الشخصي. `batch_scan.py` لا يطلب رمز دخول داخل Cron؛ بل يخرج بخطأ واضح إذا كانت الجلسة غير مخوّلة أو كانت جلسة بوت.

4. أضف القنوات من لوحة الويب أو عبر `SOURCE_CHANNELS` عند إنشاء `channels.json` أول مرة، وتأكد أن الحساب الشخصي يستطيع قراءة القنوات.

5. افتح بوت الإشعارات واضغط `/start`، ثم نفّذ مسحًا اختباريًا:

   ```bash
   python batch_scan.py
   ```

نجاح هذا الأمر يعني أن العملية اتصلت، فحصت صفقات اليوم ثم انتهت. لا تترك نسخة `main.py` تعمل بالتزامن مع المسح المجدول باستخدام ملف الجلسة نفسه.

أكواد خروج `batch_scan.py` مفيدة عند مراجعة سجل Cron:

| الرمز | المعنى |
|---:|---|
| `0` | نجاح كامل دون أخطاء جزئية. |
| `1` | خطأ منع اكتمال التشغيل. |
| `2` | ملف الجلسة يعود إلى بوت، وليس إلى حساب مستخدم شخصي. |
| `3` | جلسة المستخدم غير مسجلة الدخول أو غير مخوّلة. |
| `4` | اكتمل التشغيل جزئيًا، لكن تعذر حل أو ضم قناة، أو حدث خطأ في مسح قناة، أو فشلت إعادة إشعار معلق، أو فشل إرسال إشعار لصفقة أثناء المسح. |

الرمز `4` يعني أن العملية انتهت وأغلقت اتصال تيليجرام، لكنه لا يُعد نجاحًا كاملًا؛ راجع `batch_scan.log` لمعرفة القناة أو الإشعار الذي يحتاج إلى معالجة.

## جدولة المسح ثلاث مرات يوميًا

السكربت `run_batch_scan.sh` يشغّل `batch_scan.py` في المقدمة ويستخدم `flock` لمنع تداخل تشغيلين. لا يستخدم `nohup` ولا ينشئ خدمة دائمة.

1. تأكد أن `flock` متاح، ثم امنح السكربت صلاحية التنفيذ:

   ```bash
   command -v flock
   chmod 700 /home/USER/trading-bot/run_batch_scan.sh
   ```

2. اختبره بمسار Python الفعلي للبيئة الافتراضية الذي يعرضه cPanel:

   ```bash
   PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python \
     /home/USER/trading-bot/run_batch_scan.sh
   ```

   القيم الاختيارية للسكربت هي:

   - `PYTHON_BIN`: مفسر Python، والافتراضي `./venv/bin/python`.
   - `BATCH_LOG_FILE`: ملف السجل، والافتراضي `./batch_scan.log`.
   - `BATCH_LOCK_FILE`: ملف القفل، والافتراضي `./batch_scan.lock`.

3. اعرف توقيت الخادم أولًا:

   ```bash
   date '+%F %T %Z %z'
   ```

4. إذا كان الخادم مضبوطًا على `Asia/Riyadh`، أضف في cPanel ثلاثة Cron Jobs:

   ```cron
   0 8 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   0 14 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   0 20 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   ```

5. إذا كان الخادم مضبوطًا على UTC، فالمواعيد المقابلة لـ`08:00` و`14:00` و`20:00` في الرياض هي `05:00` و`11:00` و`17:00` UTC:

   ```cron
   0 5 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   0 11 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   0 17 * * * PYTHON_BIN=/home/USER/virtualenv/trading-bot/3.11/bin/python /home/USER/trading-bot/run_batch_scan.sh
   ```

واجهة cPanel تفسّر Cron حسب **توقيت الخادم**. لا تضف `CRON_TZ=Asia/Riyadh` إلا إذا أكد مزود الاستضافة أنه مدعوم؛ وإلا حوّل الساعات كما في المثال. توقيت الرياض UTC+3 ولا يطبق التوقيت الصيفي.

## الرفع على Namecheap Shared Hosting

نمط Cron القصير مناسب للمتطلب الحالي لأنه لا يشغّل مستمعًا دائمًا. أما `main.py` فلا ينبغي تشغيله كـdaemon على الاستضافة المشتركة، لأن [سياسة الاستخدام لدى Namecheap](https://www.namecheap.com/legal/hosting/aup/) تحظر العمليات المستقلة والخدمات الدائمة. راجع أيضًا دليل [Setup Python App](https://www.namecheap.com/support/knowledgebase/article.aspx/10048/2182/how-to-work-with-python-app/) وسياسة [Cron Jobs](https://www.namecheap.com/support/knowledgebase/article.aspx/1212/22/do-you-allow-cron-jobs/).

خطوات النشر المختصرة:

1. ارفع المشروع في مجلد غير عام إن أمكن، بما في ذلك ملفات Python و`run_batch_scan.sh` و`templates/` وملفات JSON اللازمة.
2. ارفع `.env` و`crypto_listener_session.session` بأمان، ولا تضعهما في مستودع Git أو رابط ويب عام. يفضّل ضبط صلاحياتهما إلى `600`.
3. أنشئ Python App/بيئة افتراضية من cPanel وثبّت `requirements.txt`، ثم انسخ مسار Python الدقيق منها إلى `PYTHON_BIN`.
4. نفّذ `run_batch_scan.sh` يدويًا عبر SSH واختبر وصول إشعار تيليجرام.
5. أضف مواعيد Cron الثلاثة بعد التحقق من توقيت الخادم.
6. راقب `batch_scan.log` بعد أول موعد وتأكد أن العملية انتهت دون بقاء نسخة أخرى.

لا تستخدم `keep_alive.sh` أو `nohup` لهذا النمط. ملف `keep_alive.sh` مخصص فقط لخادم يسمح بعملية مستمرة عند اختيار الوضع اللحظي.

## الاستماع اللحظي الاختياري

إذا أردت مستقبلًا التقاط كل رسالة فور وصولها بدل الانتظار لمواعيد المسح، شغّل:

```bash
python main.py
```

هذا الوضع يبقي Telethon متصلًا، ويشغّل لوحة الويب على `http://127.0.0.1:5000` وأوامر الإدارة في تيليجرام، ولذلك يحتاج جهازًا يظل يعمل أو VPS يسمح بخدمة دائمة. لا تشغّله على Namecheap Shared Hosting ولا تشغّله بالتزامن مع `batch_scan.py` باستخدام ملف الجلسة نفسه.

لحماية لوحة الويب اضبط `PANEL_PASSWORD`، وإذا كان الوصول محليًا أو عبر SSH tunnel فقط فاضبط:

```env
WEB_HOST=127.0.0.1
PANEL_USERNAME=admin
PANEL_PASSWORD=ضع_كلمة_مرور_قوية
```
